# Todo Declare

日次計画 → 集中 → 夜の振り返りで、タスクをやり切る能力を育てる日本語Webアプリ。依存ライブラリなしの静的サイトです。

## 専用ログイン・保存結果の通知

保存中・完了・失敗を画面右下の通知で表示します。Friction同期は応答を確認し、未応答時はエラーを表示。

Firebase Sparkの無料枠で、一人専用のメール/パスワード認証とFirestore同期を利用します。課金設定・Cloud Run・GitHub Secrets・管理用秘密鍵は不要です。[FIREBASE_SETUP.md](FIREBASE_SETUP.md)に設定手順を記載しています。実際のFirebase Web設定は各端末の画面から入力し、GitHubや公開ファイルに含めません。Firestore側で指定UIDだけを許可するルールの公開が必要です。設定前も端末保存・バックアップは利用できます。旧backendとBACKEND_SETUP.mdは現在使いません。

## 使い方

1. 今日または明日を選び、タスク・完了条件・見積時間・重要度を記入して宣言。
2. 宣言後は計画を固定。進捗を0〜100%で記録。25分集中タイマーを併用。
3. 夜に学びと次の改善を記入して振り返りを保存。振り返り後も当日中は進捗を更新できます。完了時は実際にかかった分数を入力します。
4. カレンダーで記録を確認。未完了は新しい計画に引き継げます。
5. 提出を忘れた日は日付入力から過去日を選んで振り返り。計画がなかった日は0%になります。

達成度 = Σ(重要度 × 進捗率) / Σ重要度。日付変更時の達成度が50%未満なら翌日は対象サイト合計20分/日、50〜79%なら40分/日、どちらも30秒の追加待機。80%以上なら翌日は制限なし。当日の振り返り・進捗で当日の制限を早期解除しません。日付変更後の進捗は編集不可です。小規模タスクは宣言とは別枠で、達成度には含めません。カレンダーで見積・実績分数と小規模タスクも確認できます。

日付はブラウザーのローカル時刻を使用します。ページを閉じている場合、アプリは次回読み込み時に過去日を確定し、Frictionは同期済みの進捗から判定します。別端末で閉じる直前に同期されていない変更は、Frictionが取得するまで反映されません。自己申告・端末時計・バックアップの改変を防ぐサーバー締め切りではありません。

ログインはFirebase SDKの永続セッションで再読み込み後も復元します。パスワードそのものはアプリに保存しません。通知時刻は記録と同じFirestoreデータに保存して共有します。通知の許可・Frictionの導入と接続設定は各端末で必要です。編集中に別端末が更新した場合は入力保護のため警告し、手動で最新データを読み込む方式です。

## Friction連携

隣の `friction` リポジトリに連携を実装しています。Chrome/Edgeの拡張機能管理で再読み込みし、通知権限を許可してください。

1. Friction設定の「Todo Declare URL」に、このアプリの**完全なURL**を登録（末尾スラッシュも一致）。
2. アプリの「通知と連携」で「同期する」。接続済み表示を確認。
3. 当日計画（初期08:00）、翌日計画（20:00）、振り返り（21:00）が未提出なら、Frictionの有効な制限対象サイトをロック。登録日以降の過去の未提出振り返りも対象。
4. 拡張機能は1分ごとに条件を確認し、通知を1日1回送信。既に開いている対象サイトもロックします。通知クリックでアプリが開きます。

URLはworker側で送信元のトップフレームと照合し、ほかのページからの同期を拒否。ページを閉じても拡張機能に同期済みの状態は残ります。同期前から未提出ロックを有効にするため、登録直後はアプリで同期してください。

## 制約とプライバシー

- 未ログイン時は端末内保存、Firebase設定後のログイン中は本人のクラウド領域に保存します。定期的にJSONバックアップを保存してください。
- Web単体は対象サイトを制限できません。Frictionは自己管理用のオーバーレイであり、拡張無効化やブラウザ変更に対する強制力、ネットワークレベルの遮断はありません。
- ページ単体の通知はページを開いている間のみ。拡張通知もブラウザ終了中、スリープ中、OSの通知拒否時は届きません。起動後に未提出を確認します。
- タイムゾーンと時刻は端末のローカル設定。ブラウザの時計や保存データの改変に耐える仕組みではありません。
- クラウド利用時はログイン中本人のFirebase領域へタスクを送信します。閲覧時間はFriction内に保存。Pagesの公開ファイルに個人のタスクデータは含まれません。

## 開発

Node.js 22以上。`npm start` → http://127.0.0.1:4173/ 。`npm test` で計算・バックアップ検証を確認。

## GitHub Pages

独立リポジトリのmainブランチにpushし、Settings → Pages → Sourceを「GitHub Actions」に設定します。`.github/workflows/pages.yml` がテスト後に `dist` を公開。相対パスなのでプロジェクトPagesのサブパスに対応します。パッケージのインストール・ビルド処理は不要です。
